# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Acadmate is an academic advising web app for students, faculty advisors and administrators (team project F2026-Team3).

- `frontend/`: React 19 + Vite 8 + Tailwind CSS 4 (JSX, no TypeScript), react-router-dom 7
- `backend/`: **FastAPI** (Python 3.10+) with PostgreSQL through SQLAlchemy 2. The earlier Express/Node backend was removed on purpose, so don't restore it or use it as a reference.
- `Doumentation/`: sprint docs, personas, Jira exports, presentations and the static HTML design prototypes (`Frontend prototypes/`). The folder name is misspelled in the repo; leave it as is.

## Backend (FastAPI)

`backend/` combines two teammate branches: the layered layout from `origin/feature/backend-setup` and the SQLAlchemy/Postgres layer from `origin/feature/database-backend`. Request flow: `main.py` (app, mounts routers) → `routers/` (HTTP layer, `APIRouter(prefix="/api/v1/...")`, gets a session through `Depends(get_db)`) → `services/` (queries and business logic, take a `Session`) → `models.py` (SQLAlchemy models). `schemas/` holds the Pydantic response models used as `response_model`. `core/` holds the cross-cutting pieces from spec 01 (`.claude/specs/01-backend-foundation.md`): `config.py` (`settings`, every env var), `errors.py` (`ApiError` + handlers), `deps.py` (auth dependencies), `time.py`, `security.py`.

- Routers never query the database or build error JSON; services never import FastAPI. Both raise `ApiError` or its helpers from `core.errors` (`not_found("Student")`, `forbidden()`, `conflict()`, `bad_request()`).
- Auth (spec 02 Phase A) is cookie sessions: `POST /auth/login` stores a `sessions` row (model `UserSession`, only the SHA-256 of the token) and sets the `acadmate_session` HttpOnly cookie. `services/auth.py` holds login, rate limiting (`login_attempts`), sessions with sliding idle expiry, sign-up, reset and invite links. `issue_reset_link(db, user)` / `issue_invite(db, user, inviter_name)` (7-day link) add the token without committing and return a `mailer.Mail`; send it with `mailer.send_all([...])` after the commit so a rollback never mails a dead link. `name_from_email()` names invited users. Phase B (TOTP two-step, Google) isn't built: `needs_mfa()` returns False and `googleEnabled` is false.
- Auth dependencies in `core/deps.py`: `get_current_user`, `require_role(...)`, `get_current_student`, `get_current_advisor`, `advisor_can_see`. Tests sign in for real with `login(client, email)` from `tests/conftest.py`, or skip the cookie with the `as_user(role)` fixture; `make_user()` creates throwaway users for tests that change data.

seeded: Smith and Kim Computer Science, Natarajan Data Science, Brooks Career Services). `approvals.avg_decision_days(db, since)` is the shared average decision time per advisor (overview: 30 days, spec 32: 60). `services/admin_overview.py` builds the admin overview (spec 30): active students = distinct student users with a `sessions` row created in the window; ### Backend commands (run from `backend/`)

Local Postgres runs in Docker on host port 5433 (the container is `acadmate-fastapi-db`, volume `acadmate-fastapi-pg`):

```bash
docker start acadmate-fastapi-db      # first time: see docker run in README.md
python -m venv venv && venv\Scripts\activate   # Windows (source venv/bin/activate elsewhere)
pip install -r requirements.txt
python test_db.py          # check DATABASE_URL connectivity
python reset_db.py --yes   # drop and recreate all tables from models.py
python seed_data.py        # load demo data
pytest -q                  # tests (needs the acadmate_test database, see README)
uvicorn main:app --reload  # http://localhost:8000, interactive docs at /docs
```

Use `--port <n>` if 8000 is taken, and point `API_PROXY_TARGET` at the same port. Tests live in `backend/tests/` (pytest + `TestClient`). They run against `TEST_DATABASE_URL` (default: `DATABASE_URL` with `_test` appended), drop and reseed it each run, and need it created once: `docker exec acadmate-fastapi-db createdb -U acadmate acadmate_test`.

### How the frontend talks to the API

- All requests go through `src/lib/api.js` (`api(path, { method, body, signal, contentType })`) and, for GETs, the `useApi(path)` hook in `src/lib/useApi.js` (abort-on-change, `reload`, `setData` for optimistic updates). Screens use these rather than calling `fetch` directly.
- The base URL is `VITE_API_URL` (default `/api`). The Vite dev server proxies `/api` to `API_PROXY_TARGET` (default `http://localhost:4000`), and the request path is forwarded unchanged. To use FastAPI, set these in `frontend/.env.local`: `VITE_API_URL=/api/v1` and `API_PROXY_TARGET=http://localhost:8000`.
- Requests send `credentials: 'include'`, because the app expects cookie sessions.
- `api.js` reads errors from the `{"error": {"code", "message", "details"}}` envelope. Any other error shape falls back to a generic "Request failed (status)" message.

**The frontend was built against the removed Express API.** Sign-in works against FastAPI (spec 02 Phase A: `/auth/*` and `/users/me/badges`; TOTP and Google are not built). The student screens' endpoints now exist (specs 10–18, listed above). On the admin side the platform overview (`/admin/overview[.csv]`, spec 30), users (`/admin/users*`, spec 31), advisors (`/admin/advisors*`, spec 32), catalog (`/admin/catalog*`, spec 33), integrations (`/admin/integrations*`, `/admin/imports`, `/admin/api-keys*`, spec 35), audit log (`/admin/audit[.csv]`, spec 36), settings (`/admin/settings`, `/admin/demo/reset`, spec 37) and AI settings (`/admin/ai/settings`, `/admin/ai/test`, `/admin/ai/flags*`) exist; advisor-side meeting routes (spec 24) don't exist yet. Students are addressed as `/students/me/...` (taken from the session), not by numeric id. Until the FastAPI backend implements these routes, those screens show error states. Grep `src/` for `api(` and `useApi(` to see the exact paths and response shapes each screen expects.

### Structure

- `src/App.jsx`: the whole route tree. `/student/*`, `/advisor/*` and `/admin/*` each render inside `AppShell` with their role. Routes that aren't built use `<Placeholder>` (all of `/advisor/*`; every admin screen is built).
- `src/auth/`: `AuthContext` loads the user from `/auth/me` plus sidebar badges (`refreshBadges()` after mutations that change a count). `RequireRole` guards routes.
- `src/config/nav.js`: sidebar navigation per role.
- `src/components/ui/`: the design-system primitives. **`src/components/README.md` documents their props and usage rules.** Build new screens from these instead of new one-off styles.
- `src/components/{layout,ai,messages,admin}/`: page shell and composites shared between screens.
- `src/lib/dates.js`: date helpers (YYYY-MM-DD strings, relative labels). `status.js`: status → pill tone mapping.

## Conventions

- `.env` files are gitignored (`!.env.example` is kept), and so is `.claude/`. Copy from `.env.example`.
- `Doumentation/Sprint Planning/AI_Academic_Advisement_Sprint0.mp4` is gitignored because of its size; don't add it.
- All data is invented demo data. Real student records are covered by FERPA and need approval before use.
